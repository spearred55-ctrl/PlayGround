# BATTLE WORLD: ELITE SURVIVAL

An original, playable 3D battle-royale game for mobile browsers and Android, built with **Three.js** and **Vite**. Every island, character, weapon, texture, sound and UI element is generated by this project — no third-party game assets are used.

> **Deploy status:** the web preview and Android build are complete offline battle-royale simulations against bots. A tested, standalone authoritative Node server is included for real matchmaking/online backends, but the static preview cannot host it. See [Online / dedicated server](#online--dedicated-server) for the honest boundary.

## What is in the game

### Match loop
- **25-player solo** by default, configurable from **10–50** operatives in Settings.
- Solo, Duo, Squad and Practice modes. Practice uses a smaller bot field and is intended for warm-ups.
- Deploy → loot → rotate → survive → result screen with placement, eliminations, damage, XP, level-ups and cosmetic unlocks.
- Local bots use the same weapons, armor, healing, looting, zone rules and hit detection as the player.
- Match results update a persistent profile: matches, wins, kills, K/D, damage, best placement, play time, level and XP.
- Spectator mode after elimination, with next-target cycling and return-to-result flow.
- Victory and defeat result panels with Play Again / Return to Lobby.

### Island of Ash
- 1500 × 1500 m procedural island with beaches, water, rivers, lakes, bridges, forests, hills and mountains.
- Landmarks: **Neon City**, **Ironhold Base**, **Kestrel Airport**, **Dockside Harbor**, **Old Mill Village**, **Foundry Works**, **Bunker 7**, **Ridge**, **Aurora Array**, **Lake** and **Beach**.
- Enterable buildings, rooftops, ladders, watchtowers, bunkers, hangars, industrial yards, shipping containers, crates, fences, bridges and cover.
- Ground-height, building and prop collision; swimming; jumping; crouching; ladders; climbable rooftops.
- Dynamic sky, sun, clouds, fog, water and zone wall.
- Minimap, full-screen map, grid coordinates, altitude, compass, next-zone circle, safe-zone timer and visible boundary.
- Loot beams, hidden caches and high-tier supply spots across the island.

### Combat and gear
- Weapon classes: assault rifles, SMGs, shotguns, sniper rifles, pistols, LMG and melee.
- Per-weapon damage, RPM, magazine, reload, range, spread, recoil, zoom, mobility and fire mode.
- Rarity tiers: Common, Rare, Epic, Legendary.
- Attachments: extended magazine, tactical grip, suppressor, 2× scope and 4× scope.
- Armor, helmets and backpacks with levels and capacity.
- Ammo types: light, heavy, shells, sniper and pistol.
- Medkits, bandages, frag grenades, healing progress and throwable physics.
- Hitmarkers, headshots, damage direction indicators, kill feed, tracers, impacts, blood, explosions and camera shake.
- Reload, weapon swap, pickup/drop, inventory management and ground-loot interaction.

### Characters and cosmetics
- Original low-poly operator built procedurally from primitives.
- Custom name, outfit colors, hairstyles and unlockable skins.
- Cosmetics are visual only — they never change health, armor, speed or damage.
- Profile, service record, arsenal browser, character customizer and settings panels.
- Touch layout editor: drag every touch control, save the layout, reset it.

### Audio
- Procedural Web Audio engine: gunshots by weapon class, dry fire, reload, hit, kill, damage, explosion, pickup, heal, footsteps, grenade throw, zone warning, victory and defeat cues.
- Volume and SFX sliders; ambient island bed; audio unlocks on the first user gesture.

### Controls
**Desktop**
- `W A S D` / arrows — move
- `Shift` — sprint
- `Space` — jump
- `C` / `Ctrl` — crouch
- Mouse — look (click the canvas to capture the pointer)
- Left mouse — fire; right mouse — aim
- `R` — reload
- `E` / `F` — interact / pick up
- `Q` — swap weapon
- `1` / `2` / `3` — weapon slots
- `G` — grenade
- `H` — heal
- `Tab` — inventory
- `M` — map
- `V` — enter/exit vehicle
- `Esc` — pause / close panel

**Touch**
- Left stick — move
- Drag the right side of the screen — look
- Fire, Aim, Jump, Crouch, Sprint, Reload, Swap, Pick Up and Drive buttons
- Quick actions for pack, heal, frag, map and pause
- Layout editor in Settings → Touch Layout

## Run locally

Requirements: Node.js 20+ (tested on Node 22) and npm.

```bash
npm install
npm run dev
# open http://localhost:3000/
```

Production build:

```bash
npm run build
npm run preview
```

`npm run build` writes a static `dist/` bundle. The Vite base is `./`, so it works from a subdirectory as well as a domain root.

## Test

```bash
npm test
```

The test suite covers the optional authoritative server:

- server-side shot validation and fire-rate enforcement;
- hostile input clamping and zone damage;
- matchmaking handshake, match start, snapshot streaming, movement and HTTP health/stats endpoints.

The playable client was additionally verified in headless Chromium with Playwright at 1440 × 900 and 390 × 844 (desktop and mobile touch). The exercised flows included movement, jump, firing, reload, loot pickup, zone shrink, bot damage/kill, all panels, medkit, grenade, death result, spectator mode, return to lobby, replay, victory and touch joystick/fire controls. The final run passed **35/35 checks** with zero console/page errors.


Verified metadata:

- package: `com.battleworld.elitesurvival`
- label: `BATTLE WORLD`
- version: `1.0` (versionCode 1)
- minSdk: 24 (Android 7.0)
- target/compileSdk: 36
- SHA-256: `ba4115730d13a0dbcd83b7d0b9a9694fd6510df340d3ef58176f08f6db0a2d91`

Install on a connected device:

```bash
adb install -r release/BATTLE-WORLD-ELITE-SURVIVAL-debug.apk
```

Rebuild the APK:

```bash
npm install
npm run android:apk
```

The build script runs the web build, Capacitor sync, Gradle `assembleDebug`, then copies the result to `release/`. **Capacitor 8 requires JDK 21.** The script auto-detects `JAVA_HOME_21_X64`, `JAVA_HOME`, or a standard Temurin/OpenJDK 21 path. Android SDK platform 36 and build-tools 36 are used.

The checked-in APK is **debug-signed** for direct installation. For Google Play or a production release, create your own keystore and run a signed `assembleRelease` build; never ship a debug key.

Capacitor project: [`android/`](android/) · configuration: [`capacitor.config.json`](capacitor.config.json).

## Online / dedicated server

The static web preview and APK intentionally run **local bot matches**. A browser page cannot host an authoritative server, and this preview does not pretend to have live matchmaking.

An optional, working authoritative Node server is included:

```bash
npm run server
# HTTP + static dist: http://localhost:3000/
# WebSocket: ws://localhost:3000/ws
```

Endpoints:

| Endpoint | Purpose |
| --- | --- |
| `GET /health` | Liveness, uptime, room/player counts |
| `GET /stats` | Tick rate and per-room state |
| `GET /version` | Protocol/version metadata |
| `WS /ws` | Matchmaking, input, authoritative snapshots |

Implemented server behavior:

- room matchmaking with configurable match size (2–50) and mode;
- automatic bot fill and match start after a short delay;
- 20 Hz authoritative simulation with 10 Hz snapshots;
- server-owned health, armor, ammo, fire rate, reload, damage and kills;
- terrain-occluded hitscan validation; clients only send movement/look/fire intents, never damage;
- server-side bot AI, zone phases, zone damage, healing and match end;
- rate limiting, input clamping and JSON protocol validation;
- optional static hosting of `dist/` from the same process.

Minimal client protocol:

```js
const ws = new WebSocket('ws://localhost:3000/ws')
ws.onopen = () => ws.send(JSON.stringify({
  type: 'join', name: 'NOVA-07', mode: 'solo', matchSize: 25,
}))
ws.onmessage = event => {
  const message = JSON.parse(event.data)
  // hello, joined, snapshot, chat, room_closed
}
// Send movement/look/fire intents:
ws.send(JSON.stringify({
  type: 'input', seq: 1, yaw: 0.4, pitch: 0,
  input: { moveX: 0, moveZ: 1, sprint: true, fire: false },
}))
```

**Boundary:** the shipped client does not yet render the server snapshot stream as a live online match. The server is a tested backend/reference implementation; the static build remains a complete offline game. Wiring a production online client (prediction, reconciliation, remote-player rendering and server loot) is the next step if live multiplayer is required.

## Known limitations

- **No live online multiplayer in the static preview or APK.** Local bot matches are the working mode; the dedicated server is included and tested separately.
- No accounts, cloud saves, purchases or anti-cheat service.
- Server collision uses the height map only; full building/prop collision exists in the client simulation.
- Bots are intentionally simplified for mobile performance; they do not use every vehicle or attachment.
- The APK is debug-signed for sideloading, not Play Store distribution.
- Headless software WebGL is much slower than a real GPU; performance numbers from CI are not device benchmarks.
